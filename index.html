Dataset Pipeline

Configurable, reproducible, and streaming-first. The same YAML config + seed always produces the same corpus.

1

Download

Stream or cache FineWeb, FineWeb-Edu, Dolma, The Stack v2, and Wikipedia from Hugging Face with auto version detection.

2

Preprocess

HTML stripping, Unicode NFKC, whitespace normalization, SHA-256 dedup, length and language filters.

3

Mix

Reservoir sampling per dataset, deterministic global shuffle, sharded JSONL/Arrow output.

4

Tokenize

Tokenizer-ready text shards; SentencePiece BPE, vocab 32,000.

5

Train

Transformer, Mamba, Hybrid, HRM & TRM compatible corpora for pretraining and post-training.

Models

Two independent training tracks, both managed entirely from the CLI.

Track 1 · Dense

68.7M TransformerLM

  • Decoder-only: RMSNorm, SwiGLU, RoPE, no bias, no weight tying
  • d_model 576 · 6 layers · 8 heads · d_ff 2304 · vocab 32k
  • 2048 context · AdamW (3e-4 → 3e-5) · FP16 autocast
  • Effective batch 32 · ~3.28B tokens over ~10 epochs
  • Trained on a single Kaggle T4 over multiple resumed sessions
Track 2 · Research

70M Hybrid-MoE (32K context)

  • Block-sparse attention: window 8192 + 128-token anchor (FlexAttention)
  • DeepSeek-style MoE with shared experts
  • MuonClip optimizer with per-head QK-Clip
  • 8K → 32K context curriculum
  • From-scratch research design with literature-review verdicts

The Journey

Pretraining on free GPUs is as much an ops project as a research one.

Seven failed kernel pushes (v1–v7)

NaN losses from Muon on embeddings, wrong corpus mounts, RoPE crashes under DataParallel, a 2.1 GB fp32 logits OOM — each failure surfaced the next fix, ending in the first healthy run at ~26.4k tok/s.

Checkpoint upload / resume machinery

Every 500 steps, resume.pt is pushed as a new version of a Kaggle dataset and pulled back on boot — enabling training across 12 h sessions and account moves.

The account saga

New Kaggle accounts silently ran CPU-only with dead DNS until identity verification. A probe-kernel workflow (CUDA + DNS checks) became standard practice before any real run.

11 OOMs to a live MoE run (v4→v15)

Sub-blocked softmax, per-chunk loss checkpoints, expandable allocator segments, and per-sub-block gradient checkpoints finally flattened memory to ~3.8 GB live — first healthy MoE step at loss 23.2, 1,435 tok/s.

Dense pretraining complete

50,000 / 50,000 steps, 3.28B tokens, best val loss 4.5870. The final checkpoint is the SFT/DPO base for the post-training phase.
